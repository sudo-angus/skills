# 中文技术术语

术语问题不能只靠禁词表解决。同一个英文词在不同上下文中可能对应不同中文；逐词寻找唯一译法，往往会产生生硬直译和生造黑话。

## 术语来源的优先级

从高到低采用：

1. 项目明确维护的术语表或产品规范；
2. 当前产品 UI 和本地化资源中的稳定名称；
3. 已发布文档、接口说明和对外材料；
4. 代码库中一致使用且读者能理解的名称；
5. 行业已有的通用中文或英文术语；
6. 根据当前动作写出的普通中文。

逐词直译排在最后。没有稳定译法时，保留约定俗成的英文，通常比创造一个“看起来像中文”的新词更清楚。

## 写作前先查

生成或修改技术内容时：

- 搜索同一概念在相邻页面、字符串资源、README 和文档中的写法；
- 区分代码标识符与用户可见名称，不把变量名直接翻译成标签；
- 新简称必须在项目中已有使用，或由用户明确要求；
- 首次出现的必要缩写应能从上下文理解，长文中可在首次出现时给出全称；
- 同一概念保持同名，不为避免重复轮换词汇。

如果现有项目用法互相冲突，在当前任务范围内选择最符合产品规范和目标读者的一种；冲突会影响行为或对外兼容性时再向用户确认。

## 先说具体动作

英文工程语境常用宽泛动词，中文成品应根据实际动作选择：

- deploy：部署、发布、上线；
- push：推送、提交、下发、上传；
- apply：应用、保存并生效、执行；
- run：运行、执行、发起；
- hit：命中、触发、调用、访问；
- land：合入、落地、发布；
- ship：发布、交付、随版本上线；
- build：构建、编译、生成安装包。

不要用一个“打”覆盖部署、构建、发布、调用、写入和执行。动作不明确时先查代码或上下文。

## 高风险直译

下表是审查线索，不是无条件替换表。项目已有稳定术语或行业存在明确专名时，以实际语境为准。

| 英文或来源概念 | 根据语境优先考虑 | 默认避免 | 可能合理的例外 |
| --- | --- | --- | --- |
| contract | 合同、协议、接口约定、约束、行为保证 | 泛化使用“契约” | 契约测试、Design by Contract、法律或团队既有术语 |
| surface / facet / aspect | 页面、入口、范围、方面、侧、界面、维度 | 单独用“面”概括任意概念 | 控制面、数据面等已有系统术语 |
| plane | 层、平面、控制面、数据面，按架构语义选择 | 不加说明的“面” | 网络与分布式系统中的固定术语 |
| pin | 固定、锁定版本、置顶、保持 | 钉住 | 项目明确采用的命令或品牌表达 |
| canonical / source of truth | 基准版本、权威来源、唯一依据、主记录 | 母本、真相源 | 出版、档案等领域已有“母本”含义 |
| master / template | 主版本、模板、基准、源文件 | 母本 | 领域规范明确使用时 |
| gate | 检查项、条件、准入规则、合并条件、发布条件 | 门 | 产品名或既有 Gate 专名 |
| green / all green | 检查通过、测试通过、构建成功 | 全绿 | 团队即时聊天中的既有口语 |
| both packages are green | iOS 和 Android 构建均通过；两个安装包均验证通过 | 双包全绿 | 团队已有且只用于内部聊天的缩写 |
| owner | 负责人、维护人、对接人 | 所有者 | 资源所有权、对象所有权等字面语义 |
| source of truth | 唯一依据、权威数据源、准确信息来源 | 真相源、真理源 | 项目已有固定译名 |
| flow | 流程、调用链路、数据流、控制流 | 不加限定的“流” | 数据流、控制流等标准术语 |
| capability | 功能、能力、支持范围，按句子重写 | 到处写“能力”作为抽象名词 | 能力模型等固定概念 |
| binding | 绑定、关联、映射、约束 | 机械统一为“绑定” | 账号绑定、数据绑定等已有概念 |
| resolve | 解析、确定、查找、消除、解决 | 一律写“解析” | 域名解析、符号解析等标准语义 |

## 生造简称和组合词

出现以下情况时默认重写：

- 两个内部对象压缩成读者从未见过的组合词；
- 用单字替代完整动作，如“打、门、面”；
- 把多个状态压成口号式简称，如“双包全绿”；
- 中文词只因逐词对应英文而存在，在项目和行业中找不到使用；
- 需要作者口头解释才能明白的缩写。

替换时写清主体、动作和结果。例如，不写“包全绿”，而写“iOS 和 Android 构建均通过”。

## 最终检查

对新出现的技术词逐个确认：

- 项目中是否已有相同概念；
- 目标读者是否能在不看讨论记录的情况下理解；
- 这个中文词是否只是英文词形的镜像；
- 是否可以用更具体的动作或对象替代抽象名词；
- 保留英文是否反而更准确；
- 同一页面和相邻文档是否保持一致。
